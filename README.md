# Huawei Router Master — المرحلة 2 (v2)

تطبيق Android بـ Kotlin و Jetpack Compose لإدارة روترات Huawei 4G/5G
من الواي فاي المحلي. دخول أصلي من داخل التطبيق، بدون متصفح وبدون WebView.

**الموديل المؤكد للمستخدم: Huawei H153-381 على 192.168.8.1.**
في اختبار حقيقي (2026-11-23) ظهرت إشارة حقيقية: RSRP ‎-76 dBm، RSRQ ‎-7.0 dB،
SINR ‎2 dB، RSSI ‎-48 dBm، ‏4G LTE على B3 (EARFCN 1850) مع تجميع NR n41.

## ما في هذه النسخة (Phase 2)

1. **دخول HiLink أصلي:** `GET /api/webserver/SesTokInfo` ثم تشفير كلمة السر
   `password_type=4` (SHA256 + Base64) ثم `POST /api/user/login` مع
   `__RequestVerificationToken` وكوكي الجلسة. بدون هذا الدخول، الراوتر يرد
   على `/api/device/signal` بالخطأ `125002` (الجلسة غير صالحة).
2. **لوحة إشارة حقيقية:** RSRP, RSRQ, SINR, RSSI من `GET /api/device/signal`،
   مع Band و PCI و Cell ID و EARFCN وعرض القناة، ونوع الشبكة من
   `GET /api/monitoring/status`. تحديث تلقائي كل 5 ثوانٍ (قابل للإيقاف) + زر تحديث يدوي.
   **إصلاح خطأ العرض:** الراوتر يرجع القيم وهي تحمل الوحدة أصلاً ("-76dBm")،
   فالعميل يشيل الوحدة قبل العرض، والواجهة تضيفها مرة واحدة بس —
   فلا يظهر "-76dBm dBm-" مرة أخرى.
3. **تجميع الحامل (CA):** الأساسي LTE من `<band>` و `<earfcn>`، والثانوي NR من
   `<nrearfcn>` / `<nrband>` عندما يرجعهما الراوتر (في وضع NSA). إن لم يرجع
   الراوتر حقل NR، تظهر "—" ولا يُخترع رقم.
4. **التحكم في الشبكة والترددات — `POST /api/net/net-mode`:**
   وضع الشبكة: تلقائي (00) / 4G فقط (03) / ‏5G NSA (04) / ‏5G SA (05) /
   5G فقط NSA+SA (06). قفل LTE: B1/B3/B7/B8/B20/B28 بقناع Hex يُرسل فعلاً.
   بعد التطبيق ينتظر التطبيق 8 ثوانٍ ثم **يعيد قراءة الوضع من الراوتر** —
   إعادة القراءة هي الحكم، لأن رد الـ POST نفسه أحياناً يكون كود خطأ
   حتى مع نجاح التطبيق (سلوك موثّق في huawei-lte-api). الرد الخام
   يظهر في الواجهة عشان المستخدم يشوف اللي اتطبق فعلاً.
   > **تنبيه صريح:** طلب net-mode يحمل 3 حقول فقط (NetworkMode و NetworkBand
   > و LTEBand) — مفيهوش حقل NR. نطاقات NR المختارة في الواجهة (n1/n3/n28/n41/n77/n78)
   > تفضيل محلي فقط ولا تُرسل للراوتر. لن نرسل حقل NR وهمي.
5. **بروفايلات جاهزة (4):** أسرع 5G / تغطية أوسع / ثبات للألعاب والبث / 4G مستقرة —
   اختيار البروفايل يملأ الوضع والنطاقات، والتطبيق يتم بزر "تطبيق على الراوتر".
6. **الأجهزة المتصلة:** `GET /api/wlan/host-list` — الاسم و MAC و IP، مع تحديث.
7. **إحصائيات الاستهلاك:** `GET /api/monitoring/traffic-statistics` — سرعة التنزيل
   والرفع الحالية، وإجمالي التنزيل والرفع، ومدة الاتصال.
8. **اختبار سرعة تنزيل حقيقي:** تنزيل ملف من `https://speed.cloudflare.com/__down`
   مع قياس الوقت وعرض التقدم والمتوسط بـ Mbps. **لا يوجد اختبار رفع** — تُرك
   عمداً بدلاً من اختراع رقم.
9. **معلومات الجهاز:** `GET /api/device/information` — الاسم وإصدار السوفتوير
   **بعد فك ترميز HTML entities** (مثلاً `&#41;` تظهر ")" فلا يظهر
   `;H6619SP1C37&#41;40#&4.0.0.5` ملخبطاً)، والهاردوير والسيريال و IMEI.
10. **أبراج مفضلة:** حفظ البرج الحالي (PCI+EARFCN) **محلياً على الهاتف فقط**
    في DataStore — مكتوب في الواجهة صراحة أنه ليس قفلاً على الراوتر.
11. **واجهة عربية RTL + وضع داكن**، وحفظ اختياري لكلمة السر في DataStore.

## ما ليس في هذه النسخة — بصراحة

- **قفل الخلية (PCI):** غير مدعوم على H153-381 — لا يوجد Endpoint موثّق
  في HiLink API لقفل الخلية على هذا الموديل، لذلك لا يوجد زر قفل خلية
  في التطبيق بدلاً من زر وهمي. الواجهة تقول ذلك صراحة.
- **قفل 5G NR:** غير مطبَّق — طلب net-mode لا يحمل حقل NR (انظر التنبيه أعلاه).
- **اختبار سرعة الرفع:** غير موجود — بدلاً من رقم مخترع.

## البناء في Android Studio

1. افتح Android Studio → Open → اختر مجلد `HuaweiRouterMaster`.
2. انتظر تحميل Gradle (يحتاج إنترنت أول مرة).
3. وصّل هاتفك أو شغّل محاكي، ثم: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
4. ثبّت الـ APK على هاتفك، واتصل بواي فاي الراوتر قبل الدخول.

> لا يوجد APK جاهز هنا — المشروع كود مصدري يُبنى في Android Studio أو عبر GitHub Actions أدناه.
> أدوات "ZIP إلى APK بضغطة واحدة" على الهاتف لا تبني مشروع Gradle حقيقي،
> ومعظمها يغلّف صفحة ويب فقط ويرجع مشكلة الدخول من المتصفح.

## البناء السحابي بدون Android Studio — GitHub Actions

النسخة دي فيها `gradlew` وملف `.github/workflows/build-apk.yml`، فمش محتاج
كمبيوتر ولا Android Studio عشان تطلع الـ APK:

1. اعمل حساب على github.com (من الموبايل عادي).
2. اعمل Repository جديد باسم `HuaweiRouterMaster` (عام، وخلّي الفرع `main`).
3. من الموبايل، افتح ملف `UPLOAD-FROM-PHONE.md` اللي مع النسخة دي واتبع خطواته بالظبط:
   باختصار: هتنشئ ملف `.github/workflows/unzip.yml` جوه GitHub من المتصفح
   (انسخ محتواه من ملف `github-unzip-workflow.yml` اللي مع النسخة دي)،
   وبعدين ترفع ملف الـ ZIP ده نفسه كملف واحد — والـ workflow هيفكّه
   ويرتّب الملفات لوحده في الريبو.
   > تنبيه: موقع GitHub نفسه مفيهوش زرار "فك ضغط" جوه الريبو، ورفع مجلد
   > كامل من متصفح الموبايل مبيحافظش على بنية المجلدات — عشان كده خطوة
   > الـ workflow دي ضرورية، مش اختيارية.
4. بعد ما الـ Run بتاع `Unzip project` يخلص بنجاح، افتح تبويب **Actions** ←
   **Build APK** ← **Run workflow** (تشغيل يدوي — لازم يدوي لأن الـ Push
   اللي بيعمله الـ workflow نفسه مبيشغّلش workflows تانية) ← استنى 2-4 دقائق.
5. من صفحة الـ Run الناجح، نزّل الـ Artifact باسم `HuaweiRouterMaster-debug-apk` — جواه ملف `app-debug.apk`.
6. ثبّت الـ APK على موبايلك (فعّل "التثبيت من مصادر غير معروفة" للمتصفح/مدير الملفات لو طلب)، واتصل بواي فاي الراوتر قبل الدخول.

> الـ APK لسه متبنيش هنا — دي طريقة البناء اللي هتطلعه. لو الـ Build فشل في Actions، ابعت لقطة شاشة من آخر سطور الـ Log.
